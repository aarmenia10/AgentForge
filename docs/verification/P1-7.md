## 3. Bugs and Platform Issues

### Bug 1: Windows PowerShell Argument Stripping in Claude Code Install Snippets
- **Severity:** Low (Platform / Usability)
- **Component:** `src/lib/mcpConfig.ts` (`buildInstallSnippet` for `claude_code`)
- **Description:** On Windows PowerShell (the default shell on Windows 10/11), executing the snippet copied from the site:
  ```powershell
  claude mcp add agentforge-k8s-manifest-hardening -- npx -y https://agentforge-b10db.web.app/mcp/agentforge-registry-0.1.0.tgz --agent k8s-manifest-hardening@1.0.0
  ```
  fails with:
  ```
  error: unknown option '-y'
  ```
  PowerShell strips the bare `--` token before passing arguments to `claude.exe`, causing Claude's CLI parser to interpret `-y` as a flag to `claude mcp add`.
- **Steps to Reproduce:**
  1. On a Windows machine, open a standard PowerShell terminal.
  2. Navigate to https://agentforge-b10db.web.app and open any agent.
  3. Navigate to **Add to Claude / Cursor** -> **Claude Code** and copy the command.
  4. Paste and run in PowerShell.
  5. Observe `error: unknown option '-y'`.
- **Workaround:** Prepend `cmd /c` or use the PowerShell stop-parsing symbol `--%`:
  ```cmd
  cmd /c "claude mcp add <name> -- npx -y <url> --agent <id>@<version>"
  ```
